Educational Prototype | C++ + Modern Fortran | 2025

Epic Hybrid Banking System

Bridging Generations of Technology

Modernization doesn't always have to mean replacement.

An independent experiment by Leslie Brockman

01 / The question

The Inspiration

The project began with a university assignment involving an array and a three-page IT proposal. I expanded that starting point into an independent experiment inspired by NASA's Voyager spacecraft and the broader challenge of preserving legacy technology.

Can modern software communicate with older programming languages without replacing the existing system?

The experiment explores software interoperability between C++ and modern Fortran. Voyager provided inspiration for thinking about long-lived systems; this project does not demonstrate compatibility with actual Voyager hardware.

02 / Connecting the layers

The Technical Approach

A C++ application handles accounts and console interaction, while a Fortran calculation layer supplies mathematical routines. A C-compatible interface connects the two languages.

C++ application layer

  • Account management with checking and savings account classes
  • Object-oriented inheritance and polymorphism
  • Deposits, withdrawals, and account information
  • Console-based user interaction

Fortran calculation layer

  • Interest calculations
  • Service-charge calculations
  • Experimental financial risk simulation

Integration

  • Fortran ISO_C_BINDING
  • C++ extern "C" declarations
  • Shared-library compilation and linking
  • A shell build script

03 / Investigation and learning

Development Challenges

Working through modern Fortran with a textbook meant learning a new language while also investigating tooling and compatibility errors in VS Code. Getting the layers to work together required testing, revisiting assumptions, and investigating how each language and its tools handled the interface.

I used AI as a debugging and research assistant to investigate errors and explore possible explanations. The precise cause of those errors was not conclusively established. The experience reinforced the importance of checking suggestions through testing and continuing to learn across languages.

04 / Outcomes and boundaries

Results and Limitations

Achieved

  • Successfully executed the hybrid C++/Fortran application
  • Demonstrated communication between the two languages
  • Implemented banking operations and mathematical integration

Limitations

  • An educational prototype, not a production banking application
  • No claim of security certification or comprehensive testing
  • The Monte Carlo risk-analysis routine remains experimental and requires correction and validation
  • No demonstrated reduction in hardware waste or storage consumption

05 / Looking forward

Reflection

Modernization doesn't always have to mean replacement.

This experiment strengthened my interest in interoperability, legacy software preservation, and using modern tools to extend existing systems. Connecting two languages offered a practical way to explore that idea while learning where further correction and validation are still needed.
